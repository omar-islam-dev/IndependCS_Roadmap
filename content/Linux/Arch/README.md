# Why am I documenting Arch Linux?
- Because **Arch Linux** is a "Joker" Distro: Since it's minimal and places all the responsibility on you, it serves as an excellent way to truly learn Linux basics and internals.
  
## But why Arch? Why not Slackware, Gentoo, or NixOS?
- **Arch** is the Sweet Spot: pacman is a powerful package manager that I can depend on without worrying about "Dependency Hell."
- **Slackware:** Slackware's package manager doesn't resolve dependencies automatically. While this is great for learning the hard way (as Linus Torvalds once suggested), it's painful for daily use. I need a modern, ready-to-use distro.

- **Gentoo:** The learning curve is a literal wall! It's not practical for me right now to compile the Kernel and Desktop Environment from scratch just to use the OS. Useful? Yes. Efficient for my current time? No.

- **NixOS:** Similar learning curve issues,(I'm still working on learning NixOS, especially the Nix store, Flakes, and the Nix programming language).

- **Conclusion:** Arch is the best choice for me  (currently)

# What is the goal of this documentation?
- **Troubleshooting Reference:** A quick lookup for problems I've faced before. The **`/logs`** folder will be crucial for saving time instead of researching on internet for the same error twice.
- **Simplified Wiki:** A place to explain complex Arch Wiki articles in a friendly way.
