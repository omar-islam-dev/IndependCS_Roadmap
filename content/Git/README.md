# Why am I documenting git?
- Because git is considered one of the essential tools for any developer who wants to track the evolution of their project and the changes that happened in it.

# What will the documentation look like?
It will be a single main page that starts with an image of git’s architecture, then the basic commands of git. For each command, if it deserves a deeper explanation because it reflects an important part of the architecture, I will branch from it into a note that contains the command with its explanation — unlike the main folder, which will only list all commands + the architecture explanation image.

# Can this folder grow and expand?
- Unlike the rest of the folders and topics, **no**, unless I later decide to dive deeper into git details in the main book [Pro Git](https://git-scm.com/book/en/v2) . This may or may not happen depending on whether I need to do it or not.
